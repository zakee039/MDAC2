## 项目定位

MDAC2 是面向 Muse Dash 自制谱的本地、可解释、可人工修订的制谱工作台。用户提供音频，系统辅助完成时间轴确认、采音、排键、音符语义、相似段编排与资源打包。目标不是一次点击生成大量音符，而是生成音乐对齐、可玩、可修改、可追溯的谱面。

实际工程目录为 `E:\project\MDAC2`。用户将本次重构称为 MDAC2.0；本文统一用 MDAC2 表示新产品代际。旧 MDAC5.0 是历史独立重构工程，不能把它的包版本 0.3.1、旧 MDAC 的 0.3.1 和新产品代际混为一谈。新应用发布版本另行管理，首次可运行基线拟为 0.1.0。

最初只建立设计文档；后续已完成的工程与训练准备另见施工日志。设计描述不能单独作为已实现或质量通过的证据。

## 贯穿全部文档的硬约束

1. 同一工程只有一份当前生效的权威时间映射；预览、量化与导出消费同一版本。
2. 自动分析、人工确认、音乐质量是三个不同概念，不能用一个 confidence 表示。
3. 上游产物不可变，编辑产生新版本；旧结果可查看，但不能冒充最新结果导出。
4. 音频相似不等于应复制谱面；检测、确认和创作应用必须拆开。
5. 缺模型、失败、取消与低置信都必须可见，不能静默降级成“成功”。
6. 首个里程碑必须验证音频→可编辑谱面→游戏可加载导出，不以框架或测试数量代替业务完成。
7. 真实用户音频、密钥、模型权重不进入默认源码仓库；备份与恢复是交付功能的一部分。

## 文档维护

本目录是设计权威来源；实现现状另写实施记录，不能通过修改措辞把未完成项标成已完成。影响契约、默认模型、时基或导出格式的变更须记录原因、迁移方式、测试证据和替代方案。文件存在、历史报告存在、当前可运行是三种不同证据等级。

## 0.2 修订摘要

通用能力优先复用：BeatThis、librosa、mir_eval、wavesurfer.js。分轨改为 capability 驱动，不固定四轨；时间拟合优先简单模型，人工编辑明确秒/拍保持策略；Huey、RoFormer 先做小实验，All-In-One、Basic Pitch、OR-Tools 保持后续候选。施工按独立任务闭环，所有代码任务在本轮结束时仍为未开始。
