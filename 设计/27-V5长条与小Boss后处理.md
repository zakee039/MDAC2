# V5 长条与小 Boss 后处理

2026-10-21，用户在 V4 基础上要求新增 V5。应用版本仍为 0.4.0；V4 默认，V5 可选。此前 v0.4.0 tag/便携包已完成，本次源码改动单独记录为未发布。

## 最新用户修订：Boss 只看持续时长，不看击打数（v10）

用户否掉了以 2N 作判据的做法，直接按**合并后的区间时长**分三档：

- **< 200ms**：保留，并且**统一改成 100ms**。这一档原本是 90–121ms 的抖动噪音，统一后同档手感一致。本曲 33 个。
- **200–2000ms**：降级处理——不生成 Boss，回退到密度丢弃（`_thin` 保下来的 note 留在原位，只丢多余）。本曲 12 个，区间 360/370/480/481/540/600/600/670/710/960/1550ms，恢复 36 个 note。
- **> 2000ms**：原封不动。本曲 1 个（29.754–31.794，2040ms）。

为什么换判据：`target_hits` 只是 authoring metadata，导出时游戏按**持续时长**执行（`v5_export.py` 里写死了这条）。按 2N 判会把 110ms 的节奏点（2N=4）和 960ms 的打桩机（2N=18）当成同一类。按秒判才对得上手感。

实现落在 `v5_density.dense_groups` 的合并循环里，判据必须在合并之后（合并会改变区间长度）：

- `BOSS_SHORT_SPAN_MS=200`、`BOSS_SHORT_DURATION_MS=100`、`BOSS_DEMOTE_SPAN_MS=(200,2000)`。
- 短档的 `end` 直接改写为 `start+0.1`。区间内所有 note 都被 consumed，后面最近的同轨事件至少在 125ms 之外，所以固定 100ms 不会撞到任何保留 note。
- 降级区间不加入 `consumed`，`_thin` 的幸存者自然按原样输出，多余的落进 `dropped`。
- audit 增 `boss_span_policy`、`bosses_before/after_span`、`boss_span_fallbacks`、`boss_span_restored_notes`、`short_bosses_normalised`、`short_boss_spans_ms`；report 每项带 `span_ms` 与 `action`（`boss` / `discard_only_boss_span`）。

本曲（Cyberangel，125ms，80% 阈值）实测：合并区间 46 个 → 34 个 Boss（33 个 100ms + 1 个 2040ms），12 个降级、恢复 36 个 note。事件 598（轻 400 / 重 25 / Gemini 70 / 长条 68 / Boss 34 / 音符 1），目标定级 11.1 → 11.8（34 个短 Boss 的 2N 计入评分）。间距违规 0、结构问题 0、BMS 回读与包内 `map2.bms` 一致、工程闸门通过。

流程身份 `studio-v5-boss-span-1ms-v10`。

## 最新用户修订：人声句首不再保守（v9）

用户实机反馈"长条对于人声起始有些保守"。审计发现两处人为限制：

1. **弱句首被当成衰减尾**。`v5_holds.detect` 里新增/补充长条要求 region 的平均能量达到本轨 90 分位的 6%，否则记 `weak_decay_not_new_attack`。本曲被这条拒掉的三段都是句首：3.71–4.82（第一句人声，能量 2.4%）、118.23–119.04（5.1%）、173.88–174.33（1.5%）。人声句首常常弱于同曲高潮段，用绝对值卡等于专门卡句首。
2. **模型给的长条头只延尾不提前**。`refine` 只会把长条尾延长到检测区间末端，头完全沿用模型预测；模型晚起多少就晚多少，检测器明明知道句子从哪里开始却不用。

现在的口径：

- 弱起判据改成"能量是不是升上来的"：低于门槛的区间，若起点前后 100ms 的能量比 `rise` ≥ 1.15 仍接受；真正在衰减的尾巴 `rise` 明显小于 1，仍拒。
- 已有长条的头会回拉到检测到的人声句首，单次最多提前 500ms，且不越过同轨前一个事件（留 20ms）。
- 门槛参数化为 `vocal_relative_energy=.02`（人声）/ `mix_relative_energy=.12`（总轨），不再是写死的 0.06。

本曲（Cyberangel，125ms，80% 阈值）实测：长条 67 → 68，新增 3.71–4.82（第一句人声）、2.87–3.89、118.23–119.04 等，8 个长条头被提前（93/210/224/296/368/456/464/500ms），被拒区间从 9 个降到 4 个。事件数 592 → 591，目标定级仍 11.1；间距违规 0、结构问题 0、BMS 回读与包内 `map2.bms` 一致、工程闸门通过。

流程身份 `studio-v5-vocal-head-1ms-v9`。

## 最新用户修订：Boss 击打数落在 3–19 就不生成，回退到丢弃模式（v8）

用户实机试玩后给出确切判据：**一个 Boss 要敲多少下（2N）决定它该不该存在**。

- **2N ≤ 2 不影响体验**：N ≥ 2 才会成 Boss，所以这条实际不会触发，属于下界说明。
- **2N ≥ 20 也不影响**：这是真正的 Boss，玩家预期就是长按连打，保留。
- **3 ≤ 2N ≤ 19 直接删**：既不像重音、也不像 Boss，只会让手感变成打桩机。

第一版的实现是错的：先照常生成 Boss，再把落在 3–19 的整条 Boss **连同它吞掉的源 note 一起删掉**。用户当场指出——**这类区间不是「删掉」，而是「没生成」，应当回退到丢弃模式**。差别很大：`_thin` 判定可以保留的 note 本来能打，把它们一起删掉等于凭空抹掉 63 个合法 note，谱面被掏空。

现在的口径：合并后先算 2N，落在 3–19 的区间**不生成 Boss**，直接走 `discard_only` 同一条路——`_thin` 保下来的 note 作为普通 note 留在原位，只丢多余的那些。实现上不需要额外的恢复步骤：这类区间不加入 `consumed`，保留下来的成员自然按原样输出，被丢弃的成员自然落进 `dropped`。

因此这条规则不是「后处理删除」，而是**Boss 准入条件的一部分**：判据放在合并之后（合并会改变 N，必须看最终区间的 2N），位置在 `dense_groups` 的合并循环里。`postprocess.json` 的 `density_policy` 记录 `bosses_before_hit_band`、`bosses_after_hit_band`、`hit_band_fallbacks`、`hit_band_restored_notes`，report 里每个区间带 `action`（`boss` 或 `discard_only_hit_band`）。

本曲（Cyberangel，125 ms，80% 阈值）实测：合并后 47 个区间，击打数分布 `{4: 34, 8: 6, 10: 4, 18: 1, 22: 1, 26: 1}`；2 个区间成 Boss（26 击、22 击），45 个区间回退成丢弃模式，恢复 63 个保留 note；事件数 574 → 592，目标定级 12.0 → 11.1。间距违规 0、结构问题 0，BMS 回读与包内 `map2.bms` 语义一致，工程闸门通过。

当前流程身份 `studio-v5-boss-hit-band-1ms-v8`。若实机觉得小 Boss 太少，把上界往下调（例如只删 3–11、留下 18 击那档）即可，改动只有 `BOSS_DELETE_TARGET_HITS` 一处。

## 用户修订：长条端点按普通 note 计间距、试玩包入库（v7）

本节只覆盖长条首尾净空与导出落盘，其余（v6 的长条内可放 note、概率换轨、80% 阈值、500ms 合并、长条附近禁 Boss）保持不变。

**长条端点不再有独立净空。** V4 冻结的 500ms 尾部避让（`TAIL_GUARD_SECONDS`）在 V5 里退场：长条的头和尾就是一个普通 note 的位置，与同轨其它 note 之间只受滑块给出的同轨最小间距约束（默认 125ms）。长条内部仍然是两倍间距。这样长条结束后的 note 不必再被赶到对侧轨，长条出口处那种单轨连续猛敲的“打桩机”手感随之消失。BPM 吸附时，后一个长条的头也只需离开前一个长条尾一个间距，不再被顶到 500ms 之后。

**Boss 的长条邻域仍是 500ms。** 这条是 Boss 专属规则，不随长条端点改成间距；`hold_edges` 与 `boss_near_hold` 在 `postprocess.json` 里分开记录，便于区分两者的来源。

**试玩包存进项目。** 每次导出成功后，`.mdm` 复制到 `<项目目录>/chart/`，文件名沿用 `[定级]曲名 - 制谱人.mdm`。同名且内容相同（sha256 一致）直接复用、不重复存；同名但内容不同则追加 ` v2`、` v3` 后缀，绝不覆盖。导出历史里的一条点击后在系统文件管理器中直接选中该文件，而不是只打开项目目录。历史里早于本版、只存在于 attempt 目录的包，会在下次启动服务时自动补进 `chart/`。

当前流程身份 `studio-v5-hold-edge-spacing-1ms-v7`。上一版（v6）的规则见下一节；V5 源码尚未入库，v6 没有留逐字节快照，历史包不覆盖。

## 最新用户修订：长条内可放 note、概率换轨、间距滑块（v6）

本节覆盖上方全部“长条内净空 / 100ms 定值 / 阈值”口径，其余（80% 阈值、500ms 合并、长条附近禁 Boss）保持不变。

**长条内不再清空。** 旧的 both-lane 净空屏蔽与 `ordinary_inside_hold` 校验都已删除：落在长条时间窗内的 note 一律保留在原位置，与长条同轨的 note 也合法，只受“长条内同轨间距”约束。旧规则的思路是把长条内部当禁区，实际效果是长条区间里永远没有可打点，这条规则作废。

**长条内同轨间距 = 同轨最小间距 × 2。** 普通同轨间距由工作台滑块给出（75–175 ms，默认 125 ms，步进 5），长条内部按两倍计算（默认 250 ms），不再沿用 V4 冻结的 500 ms 判定。滑块值随项目保存、随请求传给 worker，并写进 `chart.json.options`；导出时校验一致，改过滑块就必须重新制谱。

**概率换轨。** 每个长度 ≥ 500 ms 的长条单独处理，候选是长条时间窗内、对侧轨道上的单轨 note（轻击/重击）：

- 按时间排序的第 1 个候选：50% 概率换到长条所在一轨，时间不动；
- 若第 1 个没换，第 2 个必然换；
- 换过之后该长条即结算，后面的对侧 note 不再参与换轨，留在原位由长条处理规则（两倍间距）约束。

换轨只在落点满足两倍间距时才执行，否则跳过并记录原因，不会为了让位而删掉别的 note。因此每个长条最多新增 1 个内部 note。随机数不做种子固定——用户明确不需要逐次一致，改动流程后重建缓存即可。

**项目与流程版本解耦。** 谱面记录自己所属的流程身份；流程变了只把谱面标记为需要重制（`generation_stale`），音频、封面、歌曲信息一律保留，项目不会因为改流程而打不开。字号、间距这类设置同样存在项目里，不写进冻结清单。

**导出历史。** 导出页右侧列出该项目所有已完成的试玩包（文件名、定级、时间），点击直接在文件管理器中定位到包所在文件夹；面板高度随条目自适应。

当前流程身份 `studio-v5-masher-interior-reroute-1ms-v6`。上一版（100 ms + 长条邻域禁 Boss）源码/清单快照存 `models/v5/revisions/threshold80`，旧包不覆盖。

## 最新用户修订：80% 阈值与 500ms 合并

阈值经过两次上调：用户先要求丢弃率超过 100%，随后改为 **50%**，最后定为 **80%**。当前最终口径为 `丢弃数 / 保留数 > 0.8`，恰好 80% 不触发，只丢弃多余 note。分母始终是可保留 note 数。先按现有同轨密度规则、Gemini/重击优先级计算只删不移的可保留集合；不把长条占用和尾部避让导致的丢弃计入密度比例，以免稀疏长条内部也被误算为过密。密度未达标的段落仅丢弃多余 note，不转换、不挪轨、不重定时。

阈值只决定“过密段是否转小 Boss”，不改变分组边界、保留顺序或合并规则，所以 50% → 80% 的差别是 Boss 数量下降、被丢弃的零散 note 增多。

只有达到阈值的 Boss 才参加合并。前段结束到后段开始的间隔 **严格小于 500ms** 时连锁合并，跨轨也适用，恰好 500ms 不合并。合并区间内的原始点击（包括中间桥接点击）按来源身份去重计数 N，2N 目标与原起止时间约定保持。

当前流程身份 `studio-v5-sustain-masher-1ms-v4`（1 ms 存储、Boss 合并规则不变，仅阈值与身份号变化）。初版、100% 与 50% 阈值的源码/清单快照存于 `models/v5/revisions/{initial,threshold100,threshold50}`，原验证与试玩包不覆盖。边界测试覆盖恰好/超过 80%、499/500/501ms、连续合并、双轨合并、桥接去重与长条占用不抬高密度。本节覆盖下方初版“所有过密段均转 Boss”的历史范围。

## 最新用户修订：100ms 同轨间距与长条附近禁 Boss

用户在 80% 阈值之上追加两条：

1. **同轨最小间距 100ms**。V5 的普通同轨间距从 V4 的 150ms（BPM 关闭）改为固定 100ms；BPM 开启时同样以 100ms 为下限，网格吸附不变。长条内部仍沿用冻结的 500ms 规则，不放宽。
2. **长条附近不再允许 Boss**。过密段只要与任一长条区间相交，或落在长条首尾 ±500ms 内（与既有尾避让窗口一致），就不再转小 Boss，只按密度丢弃多余 note，记录为 `hold_proximity`。长条内部因此既没有普通 note，也没有小 Boss。

阈值仍是 **80%**，分组、保留顺序与 500ms 合并规则不变。

实现上，`studio_timing_v4.py` 被 V4 清单逐字节绑定，不能改，因此新增 `strategies/v5_spacing.py`，用同一套解析循环但替换普通同轨阈值（100ms）；长条内部对仍调用冻结的 V4 判定。`v5_density.py` 改为接受长条区间，并使用 V5 的 100ms 判定做密度分组与前向删除。

当前流程身份 `studio-v5-sustain-masher-1ms-v5`。80% 阈值版本的源码/清单快照另存于 `models/v5/revisions/threshold80`；试玩包与旧验证不覆盖。

## 已确认语义

- 长条持续期间，两条轨道都不允许其它 note；允许小 Boss，也允许合法的对轨长条。
- 整段过密的 N 个逻辑 note 合成一个小 Boss，目标 2N 次；Gemini 按一个逻辑 note 计数。
- 用户接受按原密集段起止时间导出。不能把 2N 说成游戏内可强制的上限或打满即退避。
- 原始音频、手工谱、项目、已交付包与冻结版本均不改写。

## 继承和替换

复用 V4 的权重选择、人声柔性加权、高强度候选和连续点击编排；新增独立 `v5_holds.py`，分别扫描 vocals/mix 的 100 Hz、96 频带能量特征，固定频谱锚点与相对能量共同判定持续段。短长条同样可延伸，缺失持续段可以独立新增，持续证据的结束点决定尾端。最长 8 秒分析窗未找到声学边界时不硬造一个尾巴；静音、短瞬态及过弱尾音不新增长条。没有逐曲特判或按用户描述硬编码 Cyberangel 的时间。

V5 使用逐点十二等分吸附，替代 V4 的拍内均匀化/超密删减，避免在小 Boss 分组前丢失 N。保留 V4 基础间距：不对齐为同轨 150 ms，对齐为每拍 4/12，完整四连仍允许 3/12。按各轨相邻超密边连接成区间，合并重叠的双轨区间，将区间内所有点击统一计入 N。两个完全同刻的点击使用最小 1 ms Boss 区间。BPM 开启时区间取吸附后的首末落点；关闭时取原 1 ms 首末落点。

长条内普通物件跨双轨清理在密集段转换之后执行，所以长条中仍可出现小 Boss。剩余普通物件沿用 V4 尾部 500 ms 避让和冲突处理。BPM 舍入若把合法的 501 ms 后续长条间距压成 500 ms，将后一个头移到下一网格，保留声学尾端。没有恢复设计22明确搁置的交替链合并。

歌曲首尾各 5 秒内，单轨轻/重击的局部混音能量低于整曲 p90 的 3%、且不为静音时可转 `23` 音符；中段、Gemini、长条和小 Boss 不因此改类。此阈值是未校准启发式。

## 表示、工作台与导出

冻结六类 `TrainingEvent`、训练标签和旧 BMS 导出器不变。V5 新增输出层 `SpecialEvent`：`masher` 记录 N、2N、时间与来源；`music` 是瞬时单轨音符。V5 独立导出 `0G` 配对及 `23`，使用 120 BPM 固定存储、1 ms 单元。2N 为 `//` 注释，不是自创加载器指令。来源是本地 CustomAlbums `Data/Bms.cs` 的映射及 `GetNoteData`：按相同代码/轨道寻找结束标记生成 Length。

工作台改用可扩展策略目录，旧 `studio_models.py`、旧 worker 和所有 V4 绑定源文件保持原 SHA。新排队请求按其自身 strategy_id 选择 V5 worker；旧请求仍使用旧入口。V5 参考定级按 2N 目标展开工作量，使用独立算法身份 `mdac-rule-rating-v5-target-v1`，明确标记非游戏强制连击数。导出仍需用户确认当前定级。
