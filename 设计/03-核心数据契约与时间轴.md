# 03 核心数据契约与时间轴

## 1. 身份与版本

区分 app_version、schema_version、producer_version、model_hash、policy_hash 和 project_revision。应用升级不必让全部缓存失效；任何影响输出的算法/权重/参数改变必须改变请求身份。

统一 ArtifactEnvelope 必含：artifact_type、schema_version、request_key、payload_hash、artifact_hash、inputs（上游 artifact ID/内容哈希）、producer（算法版本/权重/依赖身份）、options_hash、payload。运行时间、机器路径、日志不放入决定内容哈希的载荷，而保存在 RunRecord。JSON 禁止 NaN/Infinity，固定序列化规则并严格校验；未知字段须显式迁移，不能猜测补默认。

request_key 标识“请求”；artifact_hash 标识“结果”。GPU 或随机算法可能同请求不同结果，因此一个 request 可以对应多次 RunRecord/产物，缓存只复用已完成且匹配复用策略的结果，不覆盖旧结果，也不承诺未经验证的逐字节确定性。

## 2. AudioAsset 与变换

原始字节必须保留 original_sha256、字节数、容器信息。解码后的 CanonicalAudio 保存固定格式下 PCM 身份、采样率、声道布局、sample_count、解码器版本和规范化参数。原始文件不同但解码内容相同是否复用，由明确的 PCM 规范和版本决定，不能靠标题判定。

AudioTransform 记录原始/规范化/预览/导出之间的裁剪、补零、重采样和增益。无变速时使用 sample-based 精确映射；若未来支持拉伸，必须单独版本化映射，不能隐藏在转码命令里。所有音轨引用同一规范化音频时间原点。

## 3. TimingObservation / TimingRevision

Observation 保存 tracker 观测，不改变其原始时刻；Revision 保存用户当前采纳的解释。

| 字段 | 含义 |
|---|---|
| beat_times / downbeat_times | 秒坐标中的观测与修订结果，严格递增 |
| pulse_unit | 一个 tracker 脉冲对应的全音符比例 |
| meter_segments | 拍号分子/分母与起始音乐位置 |
| bar_origin | 指定小节起点，允许弱起音符位于其前方 |
| mapping_anchors | 音频秒与四分拍 q 的单调锚点 |
| tempo_candidates | 倍/半、复拍解释等候选及来源 |
| quality | 一致性分数、残差、覆盖区间、告警 |
| review | pending/accepted/rejected、确认者与理由 |
| lineage | 来源 observation/revision、编辑操作及策略指纹 |

核心公式：quarter-BPM = pulse-BPM × pulse_unit × 4；小节四分拍数 = N×4/D。6/8 二分感的 pulse_unit 为 3/8；80 pulse-BPM 等于 120 quarter-BPM。

## 4. 唯一权威时间映射

定义 t(q) 为严格单调的分段线性函数，q 为四分拍坐标，t 为规范化音频秒数。反函数 q(t) 必须存在。锚点间局部 quarter-BPM = 60×Δq/Δt；禁止用整首一个 BPM 代替局部速度。

原始检测 beat 可有抖动，不直接自动变为大量 BPM 事件。拟合器生成可编辑锚点，保存相对观测的残差。用户批准的是该映射版本；预览、网格生成、量化、相似对齐、导出均使用它，而不是分别使用检测列表和另一套平均 BPM。

拟合容差、最短段与可导出复杂度是版本化策略。不能同时满足音乐对齐和 BMS 表达限制时，阻止默认导出并让用户确认简化；简化生成新时间修订，不能只在导出器悄悄近似。

拟合先比较固定速度模型，再按证据增加分段，最后才使用更细的渐变近似。目标函数结合稳健残差与段数/复杂度惩罚；固定速度已满足误差预算时不增加微小变速。输出模型类型、段数、残差分布与拒绝原因，所有选择参数进入 policy_hash。

弱起可在内部使用负 q，但音频 t 不能负。导出器显式添加音乐坐标偏移/前导小节或音频补零，映射记录进 ExportManifest。末拍以后的映射外推范围必须受音频时长和 policy 限制。

## 5. 人工确认与编辑

EditRecord：操作 ID、基底指纹、操作类型、参数、执行者、理由、时间、结果指纹。接受某份自动结果与编辑其节拍是两个命令。

早期 5.0 支持 1x/2x/0.5x 与拍号重标注；MDAC2 增加受控 beat 插入、删除、拖动和 downbeat 修改。所有操作提交前校验：单调性、时间范围、拍号边界、锚点可逆性、网格退化和导出误差。人工状态不会把模型置信度改成 1.0。

跨 TimingRevision 迁移谱面必须声明 position_policy：keep_audio_time 或 keep_musical_position。前者用旧 t(q) 保持头尾秒数，再以新 q(t) 重建音乐坐标；后者保持头尾 q，以新 t(q) 求秒数。每种策略先计算 diff/冲突再确认，校验正时长、音频边界、人工锁和量化变化。音频事件证据保留原秒坐标，不因迁移丢失。

评测真值另需 reference_eligibility（标注来源、复核流程、允许用途）。provider 名称为 human_confirm 不是充分证明，禁止仅靠一个字符串把结果升级为金标准。

## 6. StemBundle

StemBundle 是带明确语义的可变轨道集合，不强制 bass/drums/other/vocals 四轨。provider 的 OutputProfile 声明实际输出（如 vocals+accompaniment 或四轨），consumer 声明 required/optional capabilities。缺必需轨道时明确缺能力；经选择切到 mix_only 后形成新运行身份，不能制造空轨满足 schema。

每轨包含唯一角色名、音频资产 ID、hash、声道、sample_count、采样率、能量摘要和 provenance（model_output/derived）。accompaniment 可为两轨模型原生输出，也可为三轨混合等 DerivedAudioArtifact；必须记录具体来源。统一角色别名不等于认定内容等价，例如某模型的 other 未必是完整伴奏。

长度、延迟和重建差异都要校验；仅“相差不超过 0.5 秒”不足以证明音轨对齐。固定短样本做脉冲/互相关检验，偏移超策略门槛则要求处理或拒绝。内容哈希证明未变，不证明分离质量。

## 7. OnsetSet、ChartIR 与编辑覆盖

OnsetCandidate：ID、音频时间、q、证据轨、候选分数、局部声学证据、量化前后误差。SelectedOnset 引用候选或 manual 来源，记录选留理由。

ChartEvent：稳定 ID、q（建议分数表示用于量化网格）、lane_mask=[ground,air]、semantic、accent、duration_q、来源 event/candidate、人工锁定标记。Gemini 是业务语义与双轨实体映射，不是第三条物理轨。Hold 在领域层拥有明确占用区间；游戏对象映射属于 exporter profile。

ChartRevision 引用 timing、选点、编排与语义策略、事件列表和用户补丁。排键/语义阶段默认不得移动 q；增删/移动必须记录为显式编辑。人工补丁与生成基底分离保存，再生成遇到无法自动重放的补丁必须显示冲突。

## 8. StructureRelation 与 ExportManifest

StructureRelation 保存源段、目标段、时间映射依赖、对应锚点、相似证据、置信/歧义、用户确认与复用许可。检测结论与已应用谱面补丁分开。

ExportManifest 固定 chart_revision、timing_revision、音频变换、资源哈希、导出器/游戏映射版本、校验报告与包哈希。打包后 BMS 回读应与导出前 ChartIR 在允许表示误差内等价，且 Gemini 实体数不与逻辑事件数混算。
