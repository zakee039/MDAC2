## 三套编号分别记录什么

| 系列 | 含义 | 当前登记 | 变更原则 |
|---|---|---|---|
| 应用版本 | 工作台软件、接口与打包版本 | v0.1.0 | 独立于模型和制谱策略；本轮不改应用版本或 Git tag |
| V 系列 | 冻结的模型基线，以及该基线登记时附带的默认推理／编排配置 | V2，机器标识 `v2` | 权重、先验、默认配置和来源均有身份；已登记版本不可原地改写 |
| R 系列 | 基于明确 V 版本的完整制谱方案：采音选择、排键调用、后处理顺序、时间网格和导出契约 | R1，依赖 V2 | 改变制谱策略可另立 R 版本，不必重新训练或复制网络权重；必须声明所依赖的 V 版本 |

**V 不是“只含裸网络”。**历史 V2 已经冻结了 V1 的两份网络权重和编排后处理 r1.1；本规范保留这个事实，不把已存在的后处理重新归功于 R1。R1 也不是新的第三个神经模型，而是复用 V2 网络与先验、明确继承和覆盖部分行为的完整方案。

当前组成：

```text
应用 v0.1.0
  ├─ V2：采音权重 + 排键权重 + 训练集编排先验 + 冻结的原默认编排
  └─ R1（明确依赖 V2）：复用以上权重/先验，采用本次人声前瞻、网格与长条策略
```

当前只有 V2＋R1 这一配对经过本次完整运行。不能因模块看起来通用，就把 R1 无验证地套到其他 V 版本。

## V2 与 R1 的功能归属

| 行为 | V2 原冻结基线 | R1 中的实际行为 | 归属／兼容关系 |
|---|---|---|---|
| 采音网络 | 人声＋伴奏，原候选门限 0.3 | 权重不变；在确认的人声区改变候选选择，普通区回到 0.3 | 网络来自 V2；新选择层属于 R1 |
| 排键网络与生成历史 | 原曲上下文、自己的组合和长条占用历史 | 同一权重，按 R1 新落点重新整曲生成 | 复用 V2，不是只筛旧谱 |
| 减少长交叉、保留同轨三连／四连 | 已有训练集先验与连续点击编排 | 沿用 | **V2 已适用的共享后处理** |
| 高强度段候选加密 | 已有声音候选、密度限制；不按空档硬补 | 沿用，并让候选服从人声证据门控 | 共享基础模块，R1 扩展门控 |
| 相似段匹配与镜像 | 已有，放在最后一次编排 | 沿用；镜像不得改变已对齐的时间 | **V2 已适用的共享后处理** |
| 同轨冲突、特重排他、长按＋点击例外 | 已有 | 沿用，并在新时间吸附后再次检查 | 共享规则与导出验收 |
| 人声一秒前瞻 | 没有 | 从实际证据起点进入、结束即退出；门限 0.08／起音支持 0.16，最小帧间距 60ms | R1 新增；不沿用实验 r1 的两秒保持 |
| 固定时间网格 | 旧绝对时间谱，BPM 120 / 1ms 存储 | 固定 BPM 240，每拍 50 格，5ms 吸附；不估计歌曲 BPM | R1 新增时间／导出契约 |
| 长条尾补齐 | 最多 250ms、同轨、只向后延长 | 不执行此步骤 | 被 R1 明确替换 |
| 长条头尾与 note／长条对齐 | 没有本次完整端点策略 | 约 100ms 内关联，同／异轨 note 作锚点；长条头头／尾尾／尾头平均后落 5ms 格，允许延长或缩短 | R1 新增替代策略，不与旧补尾叠加 |
| 齿轮 | 后处理关闭 | 继续关闭 | 本轮没有新增齿轮投放 |

高强度检测仍是声学启发式，不是已训练的语义高潮检测器；人声确认没有声源真值标注，不能把门控后的证据一致性称为人声准确率。

## 继承和执行顺序

R1 是完整方案，不能在已经跑完 V2 全部后处理的谱上再完整跑一次 R1。否则会重复加密、重复编排或镜像，还会先做旧 250ms 补尾再执行新对齐。

实际入口从缓存的神经采音候选开始：

1. 一秒前瞻及人声候选选择。
2. 使用冻结排键模型按新落点整曲生成，保留自主历史。
3. 人声门控的高强度段候选加密。
4. 共享的连续点击编排。
5. 全事件吸附到 5ms。
6. 约 100ms 关联范围内的长条端点对齐。
7. 共享的相似段镜像，作为最后一次编辑。
8. 只读冲突检查、媒体身份检查及固定 240 BPM 导出。

因此“这个后处理也适用于 V2”包含两种情况：连续点击／相似段／高强度候选等已经在 V2；新前瞻／5ms／端点对齐可在 V2 权重上使用，当前正式命名就是 **V2＋R1**。这不要求、也不允许原地修改冻结 V2 的原行为。以后若单独选用其中部分新模块，需要另存明确方案与验收，不能仍冒称原 V2 或原 R1。
