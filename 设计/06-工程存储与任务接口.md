# 06 工程存储、任务与接口

## 1. 存储布局

```text
runtime/
  state.sqlite                  工程、修订、作业、引用、模型注册
  assets/<hash>/                原始/规范化音频与用户资源
  artifacts/<type>/<hash>/      不可变产物及 manifest
  staging/<job-id>/             未发布产物
  projects/<project-id>/        可移植工程清单与修订快照
  exports/<export-id>/          包、报告和 ExportManifest
  logs/<run-id>/                脱敏结构化日志
  trash/                        可恢复删除
  models/                       权重、来源、哈希与许可，不提交 Git
```

SQLite 是工程当前 head、作业与引用的事务权威；Artifact manifest 是内容和来源权威。工程导出清单用于可移植备份/恢复，不是另一份任意可编辑的真值。浏览器只缓存视图与草稿，不能独自决定工程状态。

## 2. 数据表职责

projects：ID、标题、head_revision、归档/删除状态。revisions：父版本、变更命令、输入引用、人工补丁。artifacts：类型、内容 hash、路径、校验状态。artifact_inputs：依赖边。jobs/runs：状态、lease、重试、日志与资源。exports：修订、包哈希、校验。model_versions：模型身份、评测、生产别名历史。

谱面事件本身存版本化产物，不为每个 Note 高频更新全局数据库。当前 head 更新使用 expected_revision 乐观锁。未知 schema 拒绝并要求显式迁移，迁移前创建快照。

## 3. 文件与数据库一致性

不能假装数据库事务能原子覆盖整个文件系统。发布协议：

1. 作业在同卷 staging 构建全部文件，关闭句柄。
2. 校验数据契约、文件哈希与 manifest；失败只留下诊断，不注册成功产物。
3. 以内容 ID 发布目录；同名已存在则深校验并复用或报冲突，不覆盖。
4. 数据库事务登记产物及输入边，标记作业成功；只有 revision 仍匹配时才能推进 head。
5. 启动时协调孤立产物和未完成作业：完整但未登记的目录可验后重新登记；staging 不能作为可导出产物。

目录级原子 rename 限同卷；跨卷必须先复制到目标卷 staging，再验证发布。进程取消/磁盘满/断电不能直接删原成功结果。需要明确文件 flush、关闭和系统可保证的持久性边界；原子重命名不等于断电后绝对不丢数据。

## 4. 作业状态机

queued → running → succeeded / failed / cancelled / interrupted。

作业保存请求键、project_revision、输入 ID、producer、参数、资源需求、stage 与 completed_units/total_units。无法估时则显示阶段，不伪造线性百分比。

worker 使用 lease + heartbeat；进程死亡或 lease 失效标 interrupted，确认旧进程退出后才重试。锁文件不能仅看 PID 存在就认定有效，需关联 run 身份与 lease。取消检查点后停止；native 调用无法响应时终止该 worker，清理权限只限该 job staging。

旧作业完成但工程 head 已变化时，产物可入历史缓存，但不更新当前工程。Retry 使用新 run_id；相同请求幂等创建或绑定已有在途作业，避免双击启动两份分轨。

## 4.1 队列后端选型与业务一致性

先做 SqliteHuey 小实验，验证 Windows 启停、重试、优先级、重启后在途任务与重复交付行为；只有通过后才用其代替通用排队实现。若适配代价过高，退回最小单机队列；不得同时维护两套正式实现。

无论后端如何选，state.sqlite 中的 Job/RunRecord 都是业务状态权威。若队列另用数据库，采用事务 outbox：工程命令和待投递记录一起提交，dispatcher 重试投递；worker 按 job_id/run_id 条件领取并去重。禁止“业务成功但队列未投递”或“重试直接推进两次 head”。

Huey revoke 不等于中断已运行的计算；作业隔离进程、GPU 配额、取消确认与旧结果不更新 head 仍由 MDAC 实现。全部外部调用以可能重复执行设计，产物发布/修订更新须幂等，而不是承诺 exactly-once。

## 5. API 草案

统一前缀 `/api/v1`，长作业返回 202 + job_id；以下是拟定契约而非现成接口。

| 接口 | 职责 |
|---|---|
| POST /projects | 创建工程 |
| POST /projects/{id}/audio | 流式导入音频 |
| GET /projects/{id} | 当前修订、产物状态和能力 |
| POST /projects/{id}/commands | 带 expected_revision 的编辑命令 |
| POST /projects/{id}/jobs | timing/stems/onsets/arrange/semantics/similarity/preview/export |
| GET /jobs/{id} | 状态、进度、错误和产物引用 |
| POST /jobs/{id}/cancel | 请求取消 |
| GET /jobs/{id}/events | SSE，支持 Last-Event-ID 与断线恢复 |
| GET /artifacts/{id} | manifest/数据，验证可访问性 |
| GET /assets/{id}/audio | 预览流，支持 Range |
| GET /exports/{id}/download | 固定导出版本下载 |
| GET /models / GET /capabilities | 注册模型与运行能力 |
| POST /model-promotions | 经评测与明确确认的晋升 |
| POST /projects/{id}/backup | 可移植备份作业 |

Command 必含 command_id、expected_revision、type、payload；结果返回新 revision 与失效摘要。错误统一 code/message/details/retryable/run_id，不暴露密钥和未授权路径。冲突 409，契约错误 422，缺能力返回明确业务错误，不静默绕过。

## 6. 缓存与清理

stage 是否可用由输入指纹和校验决定，不由“最高完成步骤”决定。内容缓存可共享，但每个工程持有引用。垃圾回收必须先计算活跃 revision、导出、训练数据、备份 pin 的可达集，生成预览清单，再经明确操作进入回收站；不自动删除用户原始音频。

## 7. 备份与恢复

源码/设计：用户确认后建立 Git 与远端策略；每个完成里程碑提交，不能只有本机未提交文件。音频/权重/大产物：独立备份，保存哈希、来源与许可，下载链接不等于备份。

备份包包含项目清单、修订、引用资产和校验清单；可选包含可再生成缓存。SQLite 使用一致性备份机制，不能运行中只复制主文件漏 WAL。备份目标须是另一个故障域；同一物理盘不同分区不能作为唯一灾备。

恢复到新目录，检查字节数、SHA-256、JSON/音频解码与工程引用闭合。加入全零文件检查作为损坏预警，但不误判合法静音音频为损坏。定期做实际恢复演练；不要在唯一原件上尝试修复、覆盖或清理。
