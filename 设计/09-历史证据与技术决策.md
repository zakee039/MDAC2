## 4. 技术资料核对（2026-09-14）

- [FastAPI Background Tasks 官方文档](https://fastapi.tiangolo.com/tutorial/background-tasks/)：说明重计算与普通后台任务的区别。MDAC2 据此将持久化长作业与 API 进程分离；本地 SQLite worker 是本设计取舍，并非官方指定架构。
- [BeatThis 官方 README](https://github.com/CPJKU/beat_this/blob/main/README.md)：提供 checkpoint 与 File2Beats 推理入口，作为适配接入依据；实际锁定 commit、权重 hash、依赖、代码与权重许可需实施时另存清单。
- [Demucs 官方 README](https://github.com/facebookresearch/demucs/blob/main/README.md)：提供分轨与模型选项说明。候选 htdemucs/htdemucs_ft 需分别验证，不把模型名称相近视为同一输出身份。

本文未声称模型已安装或最新环境已兼容；没有下载权重。旧日志中的许可名称/性能不能代替当前分发审查。

## 5. 决策记录

| ID | 决策 | 原因与代价 |
|---|---|---|
| ADR-001 | 模块化单体 + 本地 worker；先验证 SqliteHuey | 队列可复用，修订/发布/取消仍由 MDAC 管理；不保证 exactly-once |
| ADR-002 | 单一 t(q) 时间映射 | 消除预览/量化/导出双时基；拟合与表示误差必须显式处理 |
| ADR-003 | 人工审核与置信度分离 | 避免“人工确认=绝对真值”；增加标注资格管理 |
| ADR-004 | request 与 artifact 身份分开 | 容纳非确定推理；需要记录多次运行与缓存选择 |
| ADR-005 | 相似检测不自动应用 | 防止声学相似清掉目标细节；增加人工确认步骤 |
| ADR-006 | UI 阶段不代表任务完成 | 支持跳页和后台计算；需要显式依赖状态 |
| ADR-007 | 先导出闭环后训练平台 | 降低研发无闭环风险；首版质量依赖手工/规则基线 |
| ADR-008 | 原子目录发布 + 数据库协调恢复 | 文件和 DB 无统一事务；必须处理孤立产物 |
| ADR-009 | 保留源资产与 AudioTransform | 防止裁剪偏移重复应用；占用额外存储 |
| ADR-010 | 不整仓复制旧工程 | 保留已验证资产但隔离隐式依赖；需要逐模块验收 |
| ADR-011 | capability 驱动 StemBundle | 容纳两轨/四轨等模型；缺能力显式拒绝，轨道名称不等于内容等价 |
| ADR-012 | librosa 相似基线先于 CNN 重训 | 减少伪标签重学与训练成本；路径仍需约束及人工标注 |
| ADR-013 | 时间轴固定速度优先拟合 | 避免将抖动变成微小 BPM 事件；明确秒/拍保持策略 |
| ADR-014 | 标准指标复用 mir_eval | 减少自写指标差异；创作质量仍需业务指标与人工评价 |
| ADR-015 | wavesurfer 作为视图组件 | 复用波形/Regions；共享 Transport 与谱面编辑不外包 |
| ADR-016 | 实验候选不进入首发必需依赖 | RoFormer/Huey 先验证；All-In-One/Basic Pitch/CP-SAT 后置 |
| ADR-017 | 单任务交付与追加日志 | 适配 Astra 额度和小上下文；独立验收，不保证固定消息数完成 |

2026-09-15 更新：上述 ADR-011～017 及 ADR-001 修订来自第二轮审查。开源能力与来源统一见 [10-开源组件选型与验证](10-开源组件选型与验证.md)，实施状态见 [施工计划+日志](施工计划+日志.md)。这是文档决策采纳，不是安装/性能验收结论。

## 6. 不照搬的历史实现

- 不把人工确认 confidence 全部设为 1.0。
- 不以 provider.name 字符串作为 oracle 真值的唯一资格。
- 不沿用自动相似组完整覆盖目标事件的默认行为。
- 不只凭弱监督伪标签 val_loss 选择相似段生产模型。
- 不只判断文件存在和进度数字来判断有效性。
- 不保留 except/pass 吞持久化故障，也不把下载完成解释为工程清零。
- 不以“不可覆盖”阻止失败重试；未完成产物必须隔离在 staging。

上述取舍均属于本轮设计，不应回写成历史项目已具备的能力。
