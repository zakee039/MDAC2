## 1. 学习类别与映射

模型学习六个物件类别：`light`（轻击）、`heavy`（重击）、`extra_heavy`（特重击，内部名称暂定）、`gemini`、`hold`（长条）、`gear`（齿轮）。音符是轻击的来源/表现形式，不设置独立训练类别；幽灵不设置训练类别。物件是否存在与类别分开建模，空白不属于这六个物件类别。

| 原始物件 | 学习目标 | 处理规则 |
|---|---|---|
| 普通轻击及已确认的轻击变体 | light | 保留落点和轨道 |
| 突袭及倒置突袭 | light | 用户明确归为轻击；保留实际落点和轨道 |
| 重击及已确认的重击变体 | heavy | 保留落点和轨道；不擅自变成双轨或连打 |
| Boss 近身攻击中的单次非连击（1 note） | extra_heavy | 用户新增的特重击类别，标记 exclusive=true；保留实际单次落点，排他范围见下文 |
| Note 音符 | light | 参与落点、轨道与轻击类别学习；保留原始音符身份供后处理使用 |
| Ghost 幽灵 | 无 | 属于补拍，直接从学习目标中排除；不参加选点、轨道或类别监督 |
| Gemini | gemini | 保留同时双轨的瞬时事件语义 |
| 单轨长条 | hold | 保留轨道与明确的头尾 |
| 双轨长条 | hold | 双轨属性，明确共同起止；不当作 Gemini |
| 普通连打的击打部分 | heavy | 简化为起点双重击；草案按同刻地空各一个重击，不再铺连续击打；此规则不改变普通轻击 |
| 普通连打中实际存在的长按部分 | hold | 长按＋击打形式保留已有长按；只有击打则不凭空增加长按；头尾与实际轨道须核验 |
| Boss 连打持续段 | hold | 转为双轨长条；根据经过核验的连打头尾建立区间 |
| Boss 其他普通攻击 | light / heavy | 不含上述单次近身攻击；按确认的攻击类型映射，保留原落点 |
| Boss 齿轮 | gear | 保留障碍时刻及轨道 |
| 普通齿轮 | gear | 障碍类别；不混入击打起音正样本 |
| 红心、PItem 等道具 | 无 | 暂不学习；已明确 Note→light 的规则作为例外保留 |
| Boss 进退场、阶段/场景/速度等控制 | 无物件学习目标 | 保留来源；与音乐时基/控制解释分开，不转为轻击 |

其余可击打配色按经过核验的类型表归轻/重击。具体分界先按13文档的建议表审阅，未知代码保留待解释状态。非攻击控制事件不适用“其他配色归轻/重击”。普通连打的双重击与长按发生占用冲突时应显式报告，不擅自删掉长按、错开落点或改为 Gemini。

## 2. 特重击与排他事件

用户确认：Boss 近身攻击中的 **1 note、非连击** 学习为独立的特重击类别，特重击是排他事件。此规则优先于旧表中的“Boss 近身攻击→重击”。Boss 连打持续段仍按既定规则转双轨长条；不能把连击压成一个特重击，也不能仅凭 Boss 身份或一个原始标记认定为单次近身攻击。

当前草案把排他解释为：**在特重击落点时刻，两条轨道均不得与其他可交互物件共存**。包括轻击、重击、另一特重击、Gemini、齿轮和该时刻占用中的长条。排他作用域与实际击打轨道分开记录：特重击保持一个逻辑事件及原始击打轨道，不自动变成地空双重击或双轨输入。

确认的是“排他事件”属性；“同刻、双轨”的具体作用域是当前解释。尚未定义前后留空时长，不擅自添加毫秒／拍数间隔；长条尾点与特重击恰好同刻的边界处理及同刻容差，随时间／占用契约另行明确。音乐启动、BPM 等非交互控制不被排他规则禁止。

归并源谱时遇到冲突应保留双方来源、报告冲突并阻止将该冲突目标作为有效监督；不静默删除、移动其他事件或截短长条。模型选点／排键、规则校验及后处理均需遵守排他约束，后处理不能在排他位置补入幽灵或其他物件。当前仅确定规范，未实现转换、解码或碰撞处理。

## 3. 幽灵舍弃与音符保留的准确含义

“舍弃幽灵”作用于派生学习目标；已复制的原始社区谱不删除、不改写。幽灵不生成正样本、不影响目标密度或训练难度统计，也不作为普通轻击提供监督。制作逐帧/栅格负样本时，不能把“被排除的幽灵标签”直接当成明确的无事件标注；仅由幽灵造成的模糊监督位置应有独立 ignore/mask 处理，具体容差待特征时间分辨率确定。

若同一时刻还存在合法轻击、重击、音符等，必须保留这些有效对象，不能因一个幽灵存在就把整帧或整个窗口全部抹掉。排除按原始事件身份执行。

“音符属于轻击”同时作用于选点与类别监督：原谱音符位置是有效轻击落点，类别映射为 light；不能继续沿用此前“音符不作击打正样本”的提案。起点/轨道不能因为原来是道具而丢失。

## 4. 后处理来源

保留两层表示：

- SourceChart / 来源旁表：原包、原谱 hash、原始行号/通道/对象代码、原类型、原位置及转换原因。
- TrainingChart：归一化学习目标，以及明确的排除/mask 记录；不包含幽灵物件类别，音符并入 light。

原类型元数据供审查和后处理使用，不作为从音频预测目标时的模型输入，避免模型通过标签来源识别答案。后处理可以独立承担补拍幽灵和音符表现的选择；具体条件、比例和冲突规则另行确认，当前不伪造或自动应用这些规则。

转换采用单独 policy/version，不覆盖原始 raw-labels。双轨长条、Gemini 与同刻不同物件保持独立事件身份；合并类别不意味着按时间点盲目去重。

## 5. 实施检查要求

后续实现须验证：突袭／倒置突袭按 light 参与监督；单次非连击 Boss 近身攻击按 extra_heavy 参与监督且排他约束有效；Boss 连击不会因类别归并变成单次特重击；排他与长条占用／跨轨物件冲突可见，后处理不能补入冲突物件；幽灵／道具排除且同刻有效事件保留；音符按 light 参与监督；源身份可以追溯；普通连打两种形式及起点双重击、长按保留和占用冲突；Boss 连打有合法尾点且双轨占用冲突可见；Gemini、双重击与双轨长条不混淆；未知物件不会静默变轻击。ChartIR/校验器/exporter 需正式扩展并回读验收，数据准备完成不代表游戏映射已支持。
