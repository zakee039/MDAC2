# 00 背景、范围与产品原则

## 1. 可确认的历史基线

旧 MDAC 位于 `E:\project\MDAC`，Vue/FastAPI 七步流程源码尚在：上传、信息、采音、排键、配色、后优化、打包。相似段检测、训练、人工编辑和传播也存在。当前未找到原生产模型目录，不能声称旧模型已经可运行。

历史 MDAC5.0 是另起的 Python 核心包，已找到 TimingBundle、Review、Confirmation、StemBundle、BeatThis/Demucs 适配、锁集和报告的实现日志。其最后找到的合规记录写有 107 测试通过、93% 语句覆盖率，这是历史记录而非当前复测。真实 BeatThis 数据闭环、结构模块迁入、采音到导出及 UI 尚未完成。

此前检查的损坏副本曾位于 `E:\新建文件夹\D\project\MDAC5.0`：46 文件中 40 个全零、5 个含异常控制字节、1 个未发现该异常。该路径在本轮检查时已不存在；本设计不依赖它可访问，更不将全零文件当作源码。

## 2. 重构要解决的根本问题

- 时间语义混用：BPM、拍号分子、每小节四分拍数、tracker 脉冲数不能混用。
- 阶段耦合：模型推理、规则修饰、UI 状态和写盘交织，难以定位质量变化来源。
- 状态不可信：存在文件不等于匹配当前参数；失败写盘不能静默忽略。
- 自动化边界不清：相似检测输出不能直接覆盖谱面；人工批准不等于绝对真值。
- 训练指标与实际体验脱节：伪标签分数、组件 F1、完整谱面体验需要分别评估。
- 资源不可恢复：只有本地权重和未推送文档无法抵御磁盘故障。

## 3. 第一版范围

必须具备：本地工程、音频导入、节拍分析/人工校正、基础采音与人工落点编辑、两轨排键、基础音符与 Hold、冲突检查、音频和谱面联合预览、BMS/MDM 导出、检查点恢复、可靠备份。

第二批增强：多音轨分析、相似段建议与安全复用、模型切换、局部再生成、完整评测命令。

后续：训练控制台、结构模型训练、歌词声学对齐、更多合法游戏对象、多用户或远程部署。

首版不承诺：自动达到专业谱师质量、完全无需人工修正、跨歌曲检索、云端训练、所有游戏特殊对象、全部旧工程无损兼容。Boss、FR 等对象在游戏语义和读写映射未确认前不开放。

## 4. 用户与成功条件

主要用户为有基础音乐节奏判断能力的自制谱作者；提供自动建议但保留决定权。新用户可逐步确认，熟练用户可直达任一阶段查看和编辑。

一次成功制谱应满足：音乐对齐、合法可加载、节奏选择有依据、休息未被强填、人工修改不被悄悄覆盖、结果可从输入和配置复现。质量未知的建议明确标识，用户可以比较前后版本。

## 5. 技术取舍

保留旧版成熟交互经验和导出测试样例；通过隔离适配/显式转换复用，而不是整仓复制。5.0 的契约与缓存设计作为参考，不照搬其置信度归一、仅支持受限修正或缺乏真实数据的假设。

先建立最小贯通链路，后扩模型矩阵；先验证一首歌再扩到覆盖多种拍号的固定集。不得为了“架构完整”预先实现分布式队列、微服务或十种未验证 provider。
