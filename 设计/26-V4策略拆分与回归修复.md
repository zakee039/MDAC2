# V4 策略拆分与回归修复（2026-10-20）

## 版本边界

工作台选择项为「制谱策略」，R2/V2/V3/V4 分别拥有入口、后处理和节拍处理。权重身份单独登记，R2/V2 使用 V2 权重，V3/V4 使用 V3 权重；V4 没有重训。冻结的 V2/V3 源码、manifest、权重和已有包不改写。

策略登记在 `recipes/strategies/*.json`，包含先验与源码哈希；工作任务同时绑定权重 manifest 和策略 manifest。R2/V3 不再共用同一个后处理入口；V2 的节拍避让使用自己的快照。可复用冻结的声学工具和公共数据格式，不把新增规则回写到冻结代码中。

`tools/refresh_strategy_manifests.py` 是显式更新候选登记的工具，运行时不会自动刷新哈希绕过身份检查。便携包构建脚本包含 V4 登记；本次未重建已有 ZIP。

## V4 最终规则

- 普通间距检查包含轻击、重击、特重击、Gemini 和长条头，按实际占用轨道判冲突。
- 长条内部允许排键。同一长条内及长条头到内部 note 的同轨间距，有 BPM 时至少 1 拍，无 BPM 时至少 500ms。
- 长条尾不算普通 note。其所在轨道的尾前、尾后 500ms（含边界）禁止其他 note，也检查下一根长条头；不把长条自身头误作与自身尾冲突。
- 冲突时尝试合法换轨，否则丢弃；使用换轨后的候选轨道做完整检查。每个事件至多换轨一次，避免在两轨来回循环。
- Gemini 比普通 note 优先，且不会在前面的特重击处理阶段被先行删除。受长条尾等硬约束限制时，单轨冲突则保留另一轨并变为重击；双轨冲突则丢弃。
- 有 BPM：起止时间吸附到每拍 12 等分；同拍同轨普通 note（包括长条头）均匀化为 1/2/3/4 个位置，分别用 `[0]`、`[0,6]`、`[0,4,8]`、`[0,3,6,9]`。通常最小间距为 4/12 拍，完整四连允许 3/12 拍；四连例外不能放宽长条内部的 1 拍间距。
- 拍内归属从吸附后的整数格号恢复，避免 1ms 四舍五入把 127.823 BPM 的下一拍头算回上一拍。歌曲开头、结尾及变速段的部分拍不允许均匀化越界。
- 无 BPM：普通同轨最小间距 150ms；只压缩超限四连，合法的四个 150ms 间隔不降级。降为三连时保留首尾时间，选一个中间身份移到首尾中点，Gemini 也参与处理。随后仍执行换轨/丢弃检查。
- 最终检查读取完整变速表，使用与修复一致的四连、长条内部和长条尾规则；检查通过后再验证 BMS 写出与读回的语义一致。

## 播放与界面

音乐播放与 Web Audio 解锁同时从点击事件启动，鼓声解锁未完成不能阻断音乐。暂停、第二次点击、离开模块或销毁后，迟到的播放结果不得恢复播放；鼓声计时器也使用轮次隔离。手打关闭鼓声后再次勾选可恢复，音乐错误和鼓声错误分别显示。

音量滑条清除普通输入框继承的 padding/border，使用独立轨道和圆形滑块，0–100% 可达、步长 1%。音量名与百分比同一行，紧邻滑条。添加变奏点、回到开头及说明移到波形下方右侧。

`web/tests/preview-bpm.mjs` 使用真实组件与样式、合成音频提供独立检查页面，不连接工程数据库，也不启动工作台后台。浏览器已验证音乐进度前进、暂停、结束重播、滑条两端和裁剪/BPM 两个播放器互相暂停。真实扬声器听感仍需用户验收。
