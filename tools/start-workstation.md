# 本机工作台

在工程根目录执行：

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-api.lock -r requirements-jobs.lock
cd web
npm.cmd ci
npm.cmd run build
cd ..
.venv/Scripts/python.exe -m mdac2.server --root E:/project/MDAC2
```

打开终端显示的本机地址，将本次启动令牌填入页面。默认仅监听 127.0.0.1:8000；令牌不写入工程或浏览器存储。服务需要 tools/audio-decoder.md 记录的本地 FFmpeg。

新建工程 → 导入音频 → 建立手工时间轴 → 新增 Note/Hold → 保存当前谱面 → 构建 MDM 资源包 → 刷新作业状态 → 下载。当前封面是生成占位图，demo 为规范音频前 15 秒；游戏加载尚待 T033 实际验收。

自动辅助流程也已接入工作台：

1. 保存初始谱面和时间轴。已安装本地 BeatThis 权重时，可在“自动时间分析”中选择模型、拍号和脉冲单位，生成候选。先试听、修订并批准时间轴；模型结果本身不代表人工批准。
2. 在“采音 · 混音起音基线”选择难度并生成候选。查看落点、量化偏移和选留理由，按需取消候选或循环试听，预览增删差异后填写理由并采纳。人工修改、锁定以及已删除的旧自动落点受到保护。
3. 在“结构与复用”检测片段，选择候选段对，循环试听 A/B。启用目标、选择关系和允许的复用方式，逐目标确认后保存关系说明。这一步不修改谱面。
4. 选择编排参考、镜像或完整替换，先查看差异和冲突。完整替换需额外明确确认，跨边界 Hold 和锁定冲突默认拒绝。应用后保存为新修订；重开工程仍可撤销上次结构复用，但后续编辑后不允许旧撤销覆盖新工作。
5. 在下方编辑器进一步修订并保存，最后构建资源包。改变时间轴或谱面后，旧分析仍可查看；再次应用需基于当前版本重新检测和预览。

采音和结构检测当前使用混音基线；分轨模型尚未选定为默认生产方案。相似段手工边界可保存，但当前对齐仅支持完整小节特征；无法对齐的边界只作标注，不能应用复用。独立优化器已有程序接口和测试，尚无工作台操作入口。自动模型缺失或失败会明确显示，不会静默切换为成功。

这些辅助步骤需要已安装的分析依赖；本机已经配置的独立模型环境与核心环境应分别维护，勿把 D:/TORCH 的 Python 3.13 wheel 安装进核心 Python 3.12 环境。

工程保存在 runtime/state.sqlite 与 runtime/store；不要运行中只复制 SQLite 主文件作为备份。导出由 Huey 投递、独立 Windows 子进程执行；退出服务取消正在计算的导出，排队任务在重启后恢复投递。失败、取消或中断后可重新构建，生成新作业。
